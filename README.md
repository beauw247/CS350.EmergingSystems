This project involved developing a smart thermostat prototype using a Raspberry Pi, an AHT20 temperature sensor, GPIO buttons, LEDs, and an LCD display. The goal was to create a system that could monitor room temperature, respond to user input, and simulate communication with a server through UART. I selected my Python code and state machine diagram for my portfolio because together they demonstrate both the design and implementation of an embedded system.

Of everything I accomplished in this course, I think what I did particularly well was learning to troubleshoot instead of immediately assuming I had done something wrong. This was easily one of the most challenging classes I have taken. There were moments when I seriously questioned whether I would finish, particularly when the wiring instructions and my actual breadboard did not seem to agree. What started as frustration eventually became an opportunity to understand the relationship between the hardware and software rather than simply following instructions.

I still have room to improve, especially when interpreting circuit diagrams and identifying hardware problems independently. However, I have developed a much better support network through technical documentation, previous lab exercises, Python libraries, online resources, and AI-assisted troubleshooting. One of my biggest lessons was learning to test individual components before expecting the entire system to work.

The skills I gained extend well beyond this thermostat. I now find myself looking at everyday technology and mentally breaking it down into states, inputs, decisions, and outputs. State diagrams are no longer just shapes and arrows on a screen. They help me visualize how a system behaves and responds to changes. I can see how that way of thinking will transfer to future software development projects.

I also gained a better appreciation for maintainable and adaptable code. Separating the temperature readings, button responses, LED controls, and display updates into individual functions made the thermostat easier to troubleshoot and understand. Using a state machine helped organize the different operating modes, while comments and consistent naming made the program easier to follow. These same principles would make it possible to extend the project with cloud connectivity without starting over.

More than anything, this course reminded me that victory really is born in struggle. I can talk about writing software all day, but there was something different about pressing a button and physically watching my code respond. That tangible result made this one of the most difficult, yet rewarding, experiences of my computer science education.
